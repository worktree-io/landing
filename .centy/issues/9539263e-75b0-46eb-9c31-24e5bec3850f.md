# Add API versioning for future changes

Introduce versioning for all APIs to allow future breaking changes without affecting existing consumers.

## Goals
- Keep current API endpoints as-is (no migration burden on existing clients)
- Add versioned routes (e.g. `/api/v2/...`) for future changes
- Establish a versioning convention/strategy going forward

## Approach
- Current endpoints remain unversioned or treated as `v1`
- New routes introduce explicit version prefix
- Document versioning policy so future contributors follow the same pattern

## Out of scope
- Migrating existing clients
- Deprecating current endpoints (do separately when ready)
